# shelf-life — SPEC

> How long does your agent's code actually survive?

Survival analysis on your own git history. For every line added, shelf-life finds who wrote it (agent or human, and which agent), when it was added, and when, if ever, it was modified or deleted. It then shows survival curves: what fraction of agent-written versus human-written lines is still alive after 7, 30 and 90 days.

A [2026 study](https://arxiv.org/abs/2601.16809) found agent code survives *longer* across 201 projects, and nobody knows whether that's because it's good or because nobody dares touch it. shelf-life answers that for **your** repo.

## Who it's for
- Engineers and leads who want data, not vibes, on what agent code costs them over time.
- Anyone paying for agents who wants "dollars per line still alive after 90 days".

## Must have (v1)
1. **Attribution:** a commit counts as agent-authored if its message has a `Co-Authored-By:` trailer naming a known agent (Claude, Codex, Copilot, Cursor, Devin, Aider…) or its author email matches a known bot. The pattern list is configurable. Everything else counts as human. Commits and lines that can't be classified are counted and reported, never silently dropped.
2. **Line tracking:** replay history with `git log --reverse -p --first-parent`. Track each added line until it is modified or deleted. Use `-M` rename detection so moves don't count as deaths. Whitespace-only edits don't count as deaths (configurable).
3. **Survival statistics, from scratch:**
   - **Kaplan–Meier** curves with censoring (lines still alive at HEAD are censored, not "survived forever")
   - median survival
   - survival at 7, 30 and 90 days, with **Greenwood 95% intervals**
   - a **log-rank test**, agent vs human
4. **Breakdowns:** by agent, by top-level directory, by file type, and by "code vs tests".
5. **Confound check (the honest part):** also report the hazard of lines that were *modified by the same author* versus *by others*. Agent code surviving longer only because nobody touches it shows up as "never touched by anyone else".
6. **Cost join (optional):** `--transcripts ~/.claude/projects` matches sessions to commits (timestamp plus branch plus files touched) and reports **cost per surviving line** at 90 days. Matching is conservative, and unmatched commits are reported.
7. **Output:** a terminal summary, `--json`, and `--html` (a single file with SVG survival curves drawn by hand, no JS libraries).
8. **Fast enough:** 10k commits in under 60 s, with an incremental cache in `.git/shelf-life/`.
9. **Stdlib only.**

## Won't do (v1)
- Detecting AI authorship without trailers (stylometry is unreliable and unfair).
- Anything that leaves the machine.
- Cox regression (Kaplan–Meier plus log-rank only; covariates are v2).

## Expectations → test cases
Fixture repos are generated by script with controlled authorship and timestamps (`GIT_AUTHOR_DATE`).

| ID | Given | When | Then |
|---|---|---|---|
| E1 | Commits with `Co-Authored-By: Claude …`, `Co-authored-by: Codex …`, and none | Attribution | Classified as claude, codex and human; the trailer match is case-insensitive |
| E2 | A line added on day 0, modified on day 10 | Tracking | One death at t=10 |
| E3 | A line added on day 0, still present at HEAD (day 50) | Tracking | Censored at t=50, not counted as a death |
| E4 | A file renamed with no content change | Tracking | No deaths |
| E5 | A whitespace-only reindent | Tracking | No deaths by default; deaths with `--count-whitespace` |
| E6 | A textbook dataset (the standard Kaplan–Meier example from any survival-analysis reference) | KM plus Greenwood | Matches the published curve and standard errors to 3 decimal places |
| E7 | A known two-group dataset | Log-rank | Chi-square and p match the reference (R `survdiff` values embedded in the test) |
| E8 | A fixture where agent lines are never touched by others | Confound check | The report flags "agent lines rarely touched by others" |
| E9 | Transcripts with a session whose timestamps and files match a commit | Cost join | The commit gets that session's cost; ambiguous matches stay unmatched and are counted |
| E10 | A 10k-commit synthetic repo | Run | Under 60 s; the second run with cache under 5 s |
| E11 | `--html` | Output | A single file with an inline SVG, no external requests (checked by parsing) |
| E12 | A merge commit, a binary file, an empty commit | Tracking | No crash; binaries skipped and counted |
| E13 | Lockfiles, snapshots, build output, changelogs regenerated every commit | Default run | Not tracked (counted as skipped); `--include-generated` brings them back. Found on tldraw, where regenerated files made human lines "die" in 0 days |

## Launch number
Run it on 5 well-known public repos with many Claude Code or Codex co-authored commits. Publish the survival curves, the confound check, and one sentence of honest interpretation each. Commit the raw JSON.

## Done when
E1–E12 pass. The README headline is a real curve from a real repo, with its caveats next to it.
